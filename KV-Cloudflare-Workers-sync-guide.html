Cloudflare KV Workers Sync Guide

Part of the Ellivien companion toolkit series

Time: 45-75 minutes
What this adds

This guide adds cross-device conversation sync to the threaded IndexedDB companion portal. The browser still saves locally first. Cloudflare KV then acts as the shared cloud copy, so the same threads can appear on phone, tablet and computer.

What This Guide Covers

You will set up:

  • A Cloudflare account
  • A Cloudflare KV namespace called PORTAL_STORAGE
  • A Cloudflare Worker using cloudflare-worker.js
  • A secure Netlify proxy using cloudflare-sync-proxy.js
  • An auth-protected OpenAI proxy using openai-proxy.js
  • A portal password/session function using auth-check.js
  • An updated index.html with manual restore, manual cloud sync and 30-minute automatic sync
Important

Do not put Cloudflare tokens, API keys or passwords inside index.html. The browser can be inspected. Secrets belong in Netlify environment variables and Cloudflare Worker secrets.

Official references: Cloudflare's own docs explain KV bindings, KV namespaces and Worker secrets.

Files Included

  • cloudflare-worker.js - deploy this to Cloudflare Workers
  • wrangler.toml - Cloudflare Wrangler configuration template
  • index.html - updated threaded portal file
  • netlify/functions/auth-check.js - password/session function
  • netlify/functions/cloudflare-sync-proxy.js - secure server-side proxy to Cloudflare
  • netlify/functions/openai-proxy.js - auth-protected OpenAI proxy from the matching starter pack
  • netlify.toml - Netlify function configuration
  • hash-password.mjs - helper for creating the password hash

Step 1: Create a Cloudflare Account

Time: 5 minutes
  1. Go to Cloudflare sign-up.
  2. Create a free account.
  3. Verify your email address.
  4. Open the Cloudflare dashboard.
Cost

The free tier is enough for normal companion portal sync if writes are controlled. This implementation saves locally often, but writes to Cloudflare only through manual sync and the 30-minute automatic timer.

Step 2: Install Wrangler

Time: 5-10 minutes

Wrangler is Cloudflare's command line tool. You can use it for the KV namespace step, but the Worker itself is easiest to create through the Cloudflare dashboard.

  1. Open Terminal.
  2. Run:
npm install -g wrangler
  1. Log in to Cloudflare:
wrangler login

A browser window should open. Approve Wrangler access.

Step 3: Create the KV Namespace

Time: 5 minutes

In Terminal, from the folder containing wrangler.toml, run:

wrangler kv namespace create PORTAL_STORAGE

Cloudflare will return something like:

[[kv_namespaces]]
binding = "PORTAL_STORAGE"
id = "abc123yourrealnamespaceid"
  1. Open wrangler.toml.
  2. Replace PASTE_YOUR_KV_NAMESPACE_ID_HERE with the real namespace ID.
  3. Keep the binding exactly as PORTAL_STORAGE.
Do not rename the binding

The Worker file expects env.PORTAL_STORAGE. If the binding name does not match, sync will fail.

Binding versus secret

This is the part that confuses most people:

  • PORTAL_STORAGE is the KV binding. It belongs in wrangler.toml and in the Cloudflare Worker bindings.
  • CLOUDFLARE_SYNC_TOKEN is the secret token. It does not go in wrangler.toml. You add it with wrangler secret put or in the Cloudflare dashboard under Variables and Secrets.

Step 4: Create the Worker in Cloudflare

Time: 5 minutes
  1. In Cloudflare, go to Workers & Pages.
  2. Click to create a new Worker.
  3. On the method-choice screen, click Start with Hello World!
  4. Do not choose Upload your static files. That creates the wrong type of service for this guide.
  5. Give the Worker a simple name if you want to change the default.
  6. Click Deploy to create the Worker first.
  7. Once it has deployed, open the Worker and click Edit code.
  8. Open the included cloudflare-worker.js file from this guide folder on your computer.
  9. Copy all of the text inside cloudflare-worker.js.
  10. Replace the contents of Cloudflare's worker.js with that code.
  11. Save or Deploy again.
Use the Hello World route

If you start from the wrong Cloudflare creation path, later steps will become confusing very quickly. The route that worked reliably was Start with Hello World!, then Deploy, then edit worker.js.

Step 5: Create the Cloudflare Sync Token

Time: 2 minutes

The sync token protects the Worker. Without it, anyone who finds the Worker URL would be able to call the sync endpoints.

Generate a long random token:

node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

Save the token somewhere secure. You will add the same token to Cloudflare and Netlify.

Step 6: Add the Binding and Token to Cloudflare

Time: 5 minutes

On the Worker overview page in Cloudflare, add the two runtime pieces the Worker needs:

  1. Open Bindings.
  2. Add a KV Namespace binding.
  3. For the variable name, enter exactly PORTAL_STORAGE.
  4. Connect it to your KV namespace.
  5. Then go to Settings or Variables and Secrets.
  6. Add a Secret called exactly CLOUDFLARE_SYNC_TOKEN.
  7. Paste the same token you generated in Step 5.
  8. Deploy the Worker again.
Binding name and secret name must match exactly

Use PORTAL_STORAGE for the KV binding and CLOUDFLARE_SYNC_TOKEN for the secret. If either name is different, sync will fail.

Wrangler secret is optional here

You can still use wrangler secret put CLOUDFLARE_SYNC_TOKEN from Terminal if you want, but the Cloudflare dashboard route above is simpler for most people and avoids confusion about where the secret belongs.

Step 7: Save the Worker URL

Time: 3 minutes

On the Worker overview page, note the Worker URL. It will look like:

https://companion-portal-sync.YOUR-SUBDOMAIN.workers.dev

Save that URL. You will add it to Netlify as CLOUDFLARE_SYNC_WORKER_URL.

If you created a new Worker, use its new URL

If you deleted an older Worker or created a fresh one during setup, update Netlify to point to the new Worker URL. If Netlify still points to the old Worker, sync will keep talking to the wrong service.

Step 8: Add the Portal Files

Time: 10-15 minutes
  1. Open your Netlify deployment folder.
  2. Back up your current index.html first.
  3. Copy the included index.html into your Netlify deployment folder.
  4. Open the new index.html.
  5. Replace [YOUR COMPANION NAME] in the page title/header.
  6. Replace [PASTE YOUR SYSTEM PROMPT HERE] with your companion's base prompt.
  7. Copy the included netlify/functions/auth-check.js into your netlify/functions folder.
  8. Copy the included netlify/functions/cloudflare-sync-proxy.js into your netlify/functions folder.
  9. Use the included netlify/functions/openai-proxy.js, or make sure your existing OpenAI proxy verifies the same portal session token before calling OpenAI.
  10. Make sure your netlify.toml contains:
[build]
  functions = "netlify/functions"
  publish = "."
Do not lose the OpenAI proxy

The Cloudflare files only add conversation sync. They do not replace the OpenAI chat function. Your deployment still needs netlify/functions/openai-proxy.js, otherwise the portal can load but the companion will not answer. For proper password protection, the chat proxy must also reject requests without a valid portal session token.

Keep your old file briefly

Before replacing files, save a copy of the old portal somewhere safe. IndexedDB migration should preserve existing local threads, but keeping a backup is sensible.

Step 9: Create the Portal Password Hash

Time: 2 minutes

The portal uses a password gate so the Netlify sync proxy can issue a short session token. The password itself is not stored in the browser.

From this package folder, run:

node hash-password.mjs "YOUR PORTAL PASSWORD HERE"

Copy the hash it prints. You will add it to Netlify as AUTH_PASSWORD_HASH.

Then generate a session secret:

node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

Save this as AUTH_SESSION_SECRET.

Step 10: Add Netlify Environment Variables

Time: 5-10 minutes

In Netlify, go to your site settings, then environment variables. Add:

  • OPENAI_API_KEY - your existing OpenAI API key
  • AUTH_PASSWORD_HASH - the hash from Step 9
  • AUTH_SESSION_SECRET - the random session secret from Step 9
  • CLOUDFLARE_SYNC_TOKEN - the same token you added to Cloudflare
  • CLOUDFLARE_SYNC_WORKER_URL - your Worker URL from Step 7
Token must match exactly

CLOUDFLARE_SYNC_TOKEN must be identical in Cloudflare and Netlify. If one character is different, sync will fail with 401 Unauthorized.

Step 11: Deploy to Netlify

Time: 5 minutes
Deploy to the existing Netlify site

This is an upgrade to your current portal, not a brand new portal. Deploy the updated files to the same Netlify site/URL you were already using.

Do not use Add new site for this upgrade unless you deliberately want a separate empty portal. IndexedDB threads are tied to the exact site URL, so a new Netlify URL will not automatically show the conversations from the old one.

Deploy your updated portal to Netlify using your usual method.

After deploy:

  1. Open the portal URL.
  2. Enter the portal password.
  3. Check that your threads load.
  4. Open the sidebar.
  5. Open Storage & sync.

You should see:

  • Last cloud sync
  • Last sync failure
  • Threads in browser
  • Pending cloud changes
  • Cloud sync now
  • Restore from cloud

How the Sync Works

Implementation behaviour
  • Threads save locally to IndexedDB first.
  • Cloudflare KV sync runs automatically every 30 minutes.
  • The sidebar has a manual Cloud sync now button.
  • The sidebar has a manual Restore from cloud button.
  • Empty placeholder threads are not uploaded.
  • The cloud sync checks local threads against Cloudflare instead of trusting only a dirty flag.
  • The browser never sees the Cloudflare bearer token.
KV write limit gotcha

Do not change this to sync on every local save. IndexedDB saves can happen often, but Cloudflare KV writes should stay controlled. This package keeps the safer 30-minute automatic sync rhythm, with manual sync available when needed.

Testing and Verification

Test 1: Worker rejects unauthorised requests

Open Terminal and run this, replacing the URL with your Worker URL:

curl -i https://YOUR-WORKER-URL.workers.dev/api/thread-index

Expected result:

HTTP/2 401
{"error":"Unauthorized"}

Test 2: Portal cloud sync works

  1. Open the portal on your computer.
  2. Create a new thread.
  3. Send one message and wait for the reply.
  4. Open Storage & sync.
  5. Click Cloud sync now.
  6. Look for a success toast like Synced 1 thread to cloud.

Test 3: Cross-device restore works

  1. Open the portal on your phone.
  2. Enter the same portal password.
  3. Open Storage & sync.
  4. Click Restore from cloud.
  5. Confirm the thread from your computer appears.
Order matters

If one device is empty, do not press Cloud sync now first. Use Restore from cloud to pull the existing cloud copy down.

Troubleshooting

Cloud sync says 401 Unauthorized

  • Check that CLOUDFLARE_SYNC_TOKEN is set in Netlify.
  • Check that the same token is set as a Cloudflare Worker secret.
  • Reload the portal and enter the portal password again.

Cloud sync says Worker URL is not configured

  • Add CLOUDFLARE_SYNC_WORKER_URL to Netlify.
  • Use the full Worker URL, beginning with https://.

Worker deploy fails because the KV binding is missing

  • Check wrangler.toml.
  • The binding must be PORTAL_STORAGE.
  • The namespace ID must be the real Cloudflare KV namespace ID.

Threads do not appear on the second device

  • On the first device, press Cloud sync now.
  • On the second device, press Restore from cloud.
  • Make sure both devices use the same Netlify portal URL.

Cloudflare write usage rises too quickly

  • Do not reduce the 30-minute sync timer unless you understand the KV write limit.
  • Do not call cloud sync from every message save.
  • Use manual sync when you urgently need to move a thread to another device.

Final Checklist

Before you rely on sync
  • Cloudflare Worker deployed
  • KV namespace bound as PORTAL_STORAGE
  • Cloudflare Worker secret added
  • Netlify environment variables added
  • Portal password works
  • Manual Cloud sync now works
  • Restore from cloud works on a second device
